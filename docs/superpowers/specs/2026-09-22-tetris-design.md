# Tetris 游戏设计文档

## 1. 项目概述

### 1.1 目标
开发一个纯浏览器运行的俄罗斯方块游戏，交付为单个 HTML 文件，无需构建工具、无需网络请求、无需外部音频资源。

### 1.2 核心特性
- **标准俄罗斯方块规则**：7 种方块（I、O、T、S、Z、J、L）、重力下落、旋转（含踢墙简化）、消行、计分
- **扩展功能**：Web Audio API 合成音效、最高分记录（localStorage 持久化）、难度递增（下落速度随消行数提升）、方块颜色主题
- **单文件交付**：HTML + CSS + JavaScript 全部内联，双击即可运行

### 2.2 架构原则

1. **逻辑与渲染分离**：游戏逻辑层不依赖 Canvas/DOM，所有状态操作为纯函数，可独立测试
2. **单一数据源**：棋盘状态（二维数组）为唯一事实来源，渲染层只负责可视化
3. **状态机驱动**：游戏状态（准备/进行中/暂停/结束）由显式状态机管理，避免状态混乱
4. **无外部依赖**：零 npm 包、零图片、零音频文件，单 HTML 即可运行

## 3. 组件划分

### 3.1 游戏逻辑层（Game Engine）

**职责**：纯函数，无 DOM 操作，可单元测试

| 模块 | 职责 | 关键函数 |
|------|------|----------|
| `Board` | 棋盘状态管理 | `createBoard()`, `isCellFilled()`, `placePiece()` |
| `Piece` | 方块实体 | `createPiece(type)`, `rotate(piece)`, `collides(piece, board)` |
| `Game` | 游戏流程控制 | `start()`, `pause()`, `reset()`, `tick()` |
| `Score` | 计分系统 | `calculateScore(lines)`, `updateBest()` |
| `Sound` | 音效合成 | `playMove()`, `playRotate()`, `playClear()`, `playGameOver()` |

### 3.2 渲染层（Renderer）

**职责**：Canvas 绘制，无游戏逻辑

| 模块 | 职责 |
|------|------|
| `BoardRenderer` | 绘制棋盘网格、已固定方块、锁定提示 |
| `PieceRenderer` | 绘制当前下落方块、下一块预览、幽灵块 |
| `EffectRenderer` | 消行动画、得分飘字、粒子效果 |
| `UIRenderer` | 绘制 HUD（分数、等级、消行数） |

### 3.3 输入层（Input）

**职责**：将用户输入转换为游戏逻辑调用

| 输入 | 对应操作 |
|------|----------|
| ← / → 方向键 | 左右移动 |
| ↓ 方向键 | 加速下落 |
| ↑ / X | 顺时针旋转 |
| Z | 逆时针旋转 |
| 空格 | 瞬间下落 |
| P / Esc | 暂停/继续 |
| R | 重新开始 |
| 鼠标 | 开始、暂停、重置按钮 |

### 3.4 音效层（Audio）

**实现方式**：Web Audio API 振荡器合成，无需音频文件

| 事件 | 音效特征 |
|------|----------|
| 移动 | 短促方波 200Hz，0.05s |
| 旋转 | 短促方波 300Hz，0.05s |
| 消行 | 上行音阶琶音 |
| 硬降 | 低频噪声冲击 |
| 游戏结束 | 下行音阶渐弱 |

## 4. 数据流

### 4.1 核心数据流

```
键盘事件 → Input 层 → Game Engine（纯函数）→ 更新 Board 状态
                                                   │
                                                   ▼
                                          Renderer 监听状态变化
                                                   │
                                                   ▼
                                          Canvas 重绘当前帧
```

### 4.2 游戏循环（Game Loop）

使用 `requestAnimationFrame` 驱动，但逻辑更新按固定时间步长（gravity interval）进行：

```
每帧：
  1. 渲染当前状态（Canvas）
  2. 根据重力计时器决定是否触发逻辑 tick
  3. tick 内部执行：下落 → 碰撞检测 → 锁定 → 消行 → 生成新方块
  4. 如果游戏结束，进入结束状态并播放音效
```

### 4.3 状态机

```
┌────────┐     开始     ┌──────────┐     暂停/继续     ┌───────┐
│ 准备   │ ──────────▶ │ 进行中    │ ◀───────────────▶ │ 暂停   │
└────────┘             └──────────┘                   └───────┘
     │                       │
     │  结束                 │  结束
     ▼                       ▼
┌──────────┐             ┌──────────┐
│ 游戏结束  │             │ 游戏结束   │
└──────────┘             └──────────┘
```

## 5. 关键算法

### 5.1 棋盘表示

```
type Board = Array<Array<Cell>>  // 20 行 × 10 列
type Cell = 'empty' | { type: 'I'|'O'|'T'|'S'|'Z'|'J'|'L', color: string }
```

- 使用二维数组表示，`board[row][col]` 为空或已固定方块
- 顶部额外 2 行作为隐藏缓冲（spawn area），渲染时不显示

### 5.2 方块表示

```
type Piece = {
  type: 'I'|'O'|'T'|'S'|'Z'|'J'|'L',
  rotation: number,  // 0-3
  position: { x: number, y: number },
  matrix: Array<Array<number>>  // 旋转后的实际形状
}
```

### 5.3 碰撞检测

```
function collides(piece, board): boolean {
  for (每个方块单元格) {
    if (越界) return true
    if (目标格已填充) return true
  }
  return false
}
```

### 5.4 消行与计分

- 检测完整行，移除并填补空行
- 计分：单行 100、双行 300、三行 500、四行（Tetris）800，乘以当前等级
- 每消 10 行等级 +1，下落速度指数级提升

### 5.6 幽灵块（Ghost Piece）计算

幽灵块显示当前方块最终落点（受重力影响的底部位置），辅助玩家判断落点：

```
function getGhostPosition(piece, board): position {
  let ghostY = piece.y
  while (!collides({ ...piece, y: ghostY + 1 }, board)) {
    ghostY++
  }
  return { x: piece.x, y: ghostY }
}
```

### 5.7 7-Bag 随机生成

为保证每种方块出现频率均衡，使用 7-Bag 算法：

```
每次从 7 种方块中随机洗牌生成 bag，逐次取用
当 bag 为空时重新洗牌
```

## 8. 设计决策记录

### 8.1 为什么选择 Canvas 而非 DOM
- 俄罗斯方块需要高频重绘（每秒下落 1-20 次），Canvas 绘制性能稳定
- DOM 操作每个格子都会触发样式计算，大量 DOM 节点时性能下降明显
- Canvas 更适合粒子、渐变等视觉效果

### 8.2 为什么选择 Web Audio API 而非音频文件
- 无需外部资源，单文件交付更纯粹
- 可精确控制音效参数（频率、时长、音量）
- 体积更小（代码 vs 音频文件）

### 8.3 为什么使用 7-Bag 而非完全随机
- 完全随机可能导致某方块长时间不出现，影响游戏体验
- 7-Bag 保证每种方块在 7 个内至少出现一次，分布更均衡

### 8.4 为什么逻辑层与渲染层分离
- 逻辑层可独立测试，保证核心玩法正确
- 渲染层可替换（如未来支持 WebGPU 或不同视觉风格）
- 职责清晰，便于维护
